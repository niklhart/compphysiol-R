# AGENTS.md

Guidance for AI coding agents working on `compphysiol`, an R package for computational physiology and PBPK/PD modelling.

## Project Shape

- This is an R package. Core code lives in `R/`, tests in `tests/testthat/`, generated Rd files in `man/`, raw data/build scripts in `data-raw/`, and package metadata in `DESCRIPTION`/`NAMESPACE`.
- The package uses S3 classes rather than R6/reference classes. Most model components are lightweight data-frame-like objects with custom constructors, `c()`, `[`, `[[`, `names()`, `length()`, `print()`, and `as.*()` methods.
- The central user object is `CompartmentModel`, currently a list with `compartments`, `molecules`, `transports`, `reactions`, `equations`, `observables`, `parameters`, and `doses`.
- The package is in a major refactor. Prefer preserving current public behavior unless the task explicitly asks for a breaking API change.

## Development Workflow

- Prefer small, focused changes. Keep refactors behavior-preserving where possible and cover behavior changes with tests.
- Use existing constructor/add-wrapper patterns:
  - public constructors such as `compartments()`, `molecules()`, `transports()`, `reactions()`, `equations()`, `parameters()`, `dosing()`;
  - pipable mutators such as `add_compartment()`, `add_molecule()`, `add_transport()`, `add_reaction()`, `add_equation()`, `add_observable()`, `add_parameter()`, `add_dosing()`;
  - `.forward_or_use()` for add-wrapper forwarding when adding new component types or arguments.
- Do not hand-edit `NAMESPACE` or files in `man/` unless explicitly requested. They are generated by roxygen2.
- Do not regenerate `sysdata.rda` or derived data unless the task is specifically about package data. Data build scripts live in `data-raw/`.
- The repo uses `renv`; avoid changing `renv.lock` unless dependency changes are intentional.
- Never work on the `main` branch. If asked to do a change and the current branch is `main`, abort and notify about that a branch change was forgotten.

## Testing

- Run focused tests while developing, for example:

  ```r
  devtools::test(filter = "ode")
  devtools::test(filter = "wire")
  ```

- For broader verification, run:

  ```r
  devtools::test()
  ```

- Use `testthat` edition 3 expectations. Add regression tests near the behavior being changed.
- Snapshot tests exist under `tests/testthat/_snaps/`; update snapshots only when output changes are intentional.
- Some tests are intentionally skipped for unfinished refactor areas. Do not unskip or rewrite them unless the task targets that area.

## Domain And API Invariants

- Preserve the PBPK modelling vocabulary: compartments, molecules, transports, reactions, equations, observables, parameters, dosing, ODE export, and analytical/lumping utilities.
- Treat units as first-class behavior. Constructors and add-functions support NSE unit syntax such as `100 [mg]` and use the `units` package.
- Be careful with evaluation environments. The DSL supports state references like `a[molec,cmt]` and `c[molec,cmt]`; helpers in `R/DSL.R`, `R/expression-handling.R`, and `R/utils.R` are central to expression parsing/substitution.
- Wildcards are meaningful:
  - missing molecule in transports represents `<all molec>`;
  - missing compartment in molecules/reactions represents `<all cmt>`;
  - `wire()` resolves those wildcards before ODE generation.
- Source/sink compartments are represented by `NA_character_` internally, with `NULL` or `""` accepted at the user-facing boundary.
- Preserve class attributes and list-columns when manipulating data-frame-like classes. Use existing helpers such as `.combine_df_like()`, `.subset_df_like()`, `.extract_df_like()`, and `.listify_df_like()`.
- Direct `[[` extraction is intentionally blocked for several data-frame-like classes. Do not re-enable it casually.

## Refactor Notes

- `Transports` appear to be the current direction for what older code/tests may still call flows. If touching flow/transport code, inspect all of `R/Transports.R`, `R/CompartmentModel.R`, `R/lumping.R`, `R/mergeModels.R`, and affected tests before choosing names or compatibility behavior.
- `to_ode()` currently wires the model, creates depot structures for infusions, checks units, substitutes equations/parameters, builds an ODE function for `deSolve`, and returns events/observables/free parameters. Changes here have wide blast radius.
- Reactions and transports differ intentionally:
  - transports move amount between compartments and can vectorize over `from`, `to`, and `molec`;
  - reactions transform molecules within compartments and use vector inputs/outputs as stoichiometric participants.
- Keep generated function bodies human-readable where the existing code does so; this helps debug generated ODEs.

## Style

- Follow the existing base R style: S3 methods, roxygen comments, explicit helper functions, and native pipe `|>`.
- Prefer clear errors with package/domain terms over low-level R errors.
- Keep comments useful and sparse. Add comments when explaining model semantics or non-obvious evaluation/unit behavior.
- Use ASCII in new text unless editing code that already uses a specific symbol for user-facing output.

## Common Commands

Useful commands from the repository root:

```sh
Rscript -e 'devtools::test()'
Rscript -e 'devtools::test(filter = "ode")'
Rscript -e 'devtools::document()'
Rscript -e 'devtools::check()'
```

Run the narrowest useful test first, then broaden when changing shared model, unit, DSL, or ODE-generation code.
